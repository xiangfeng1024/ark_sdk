# c8t6_microcar_soil 项目需求

## 当前范围

正式流程已实现传感器采集、循迹闭环、四个直角、每角MaixCam花盆视觉对准、舵机插土采样、3秒蜂鸣报警、视觉返航、BH1750自动灯光、北斗定位和蓝牙透明上报。第四个花盆完成测量并返航后停车。

本App、DTS、IOC、Keil工程和Keil Target统一命名为`c8t6_microcar_soil`。唯一项目配置源是`c8t6_microcar_soil.dts`：`/sys`描述CubeMX控制器、GPIO/总线和组件实例，`/software`只描述任务、PID、循迹、视觉、土壤、显示和灯光策略。PC端工程路径、SDK路径、target及Reset-and-Run均由工具按同名规则自动推导。

## 传感器

- DHT11：采集温度、湿度，并显示到 OLED。
- MQ7：采集一氧化碳传感器 ADC 原始值/毫伏值，并显示到 OLED。
- MQ135：采集空气质量传感器 ADC 原始值/毫伏值，并显示到 OLED。
- BH1750：使用硬件 I2C1，与 OLED 共用总线，通过地址区分，并显示光照强度。
- 土壤湿度：上电时探针保持抬起，周期任务用前8次ADC原始值建立空载基线；原始值低于`baseline_raw-200`才判定已插入土壤并视为有效。插土状态机保持插入2秒后只接受满足该阈值的数据。
- 循迹：使用无 MCU 的 ADC + 74HC138/38 译码器逐路选择方式，采集 8 路模拟值，输出归一化值、位置和数字线状态。

## 任务分层

- `controlTask`：独立执行控制组件更新，当前目标值为 0，预留 PID/循迹控制接入点。
- `sensorTask`：每200ms采集DHT11、MQ7、MQ135、土壤和BH1750，按光照档位更新WS2812B。土壤周期值用于建立和跟踪抬起状态的空载基线，只有低于插入阈值时才允许OLED和蓝牙使用；正式插土结果优先。每1秒通过蓝牙发送一次全部传感器、北斗和视觉数据。ADC38由20ms业务任务独占采集。
- `oledTask`：每100ms读取持久传感器快照并专门绘制OLED，两个中文16x16页面每2秒轮换；每次花盆流程完成后在1秒内闪烁中文“完成”三次。
- `businessTask`：每20ms执行正式四角状态机，依次完成循迹、直角补偿、原地转弯、花盆对准、插土采样、3秒报警和视觉返航，第四角完成后停车。

## ADC38 循迹校准

`c8t6_microcar_soil.dts`的`/software/calibration`白/黑数组作为编译期默认值。上电时App读取内部Flash记录并校验magic、版本、结构长度和CRC32；记录有效则覆盖DTS默认值，空白或损坏则继续使用默认值，无需因重新校准而编译固件。当前默认值为：

```dts
ark,white = <2624 2172 3104 2016 1000 2043 1606 1476>;
ark,black = <89 84 87 92 101 85 93 89>;
```

MaixCam启动后的前10秒显示“进入循迹校准”按钮。进入后切换为纯黑背景，不显示摄像头画面；页面分别显示Flash/默认的“当前参数”和本轮“采集参数”，采集前对应行保持空白。四个24像素中文命令按钮按下后短暂变黄，另有“退出校准”按钮返回启动页。白色、黑色都成功采集前，Camera和STM32两端都拒绝写入Flash。生产固件已删除UART CLI，校准统一通过MaixCam完成。

循迹PID只使用中间6路探头，按`{-1024,-614,-205,205,614,1024}`对标定后的黑线模拟强度求加权平均，结果限制在`-1024..+1024`。最外侧0/7路不参与PID，只用于直角事件：仅左侧触发时状态偏移为`-2048`，仅右侧触发为`+2048`，两侧同时触发为`0`。

8颗WS2812B上电以白色88亮度自检200ms后熄灭。运行时BH1750每200ms采样，将`0..1500 lx`均分为8个约187.5 lx的区间，环境越暗灯光档位越高：`0..187->7`、`188..374->6`、`375..562->5`、`563..749->4`、`750..937->3`、`938..1124->2`、`1125..1312->1`、`>=1313->0`。白光RGB按`{0,12,25,37,50,62,75,88}`分配，仅档位变化时发送约240us的软件时序。BH1750不做额外校准，高分辨率模式按`lux=raw/1.2`换算；`lux_x10`必须使用`raw*100/12`。

历史`track_probe`已验证0至7通道的译码请求位、GPIO回读和ADC数据；生产固件不再编译该CLI，后续白黑校准通过MaixCam完成。

这些是编译和接口示例值，不代表实物最终标定值。

## 引脚

- ADC38 模拟输入：PB0 / ADC1_IN8。
- 舵机软件 PWM：PA6。
- 74HC138地址输出：A0=PC13、A1=PB3、A2=PB4。PC13仅驱动高阻译码输入，满足其低驱动能力限制。
- PB2不再使用，避免BOOT1复用和板级下拉影响最低地址位。PB3/PB4是JTAG复用脚；工程使用`SWJ_NOJTAG`保留SWD后可作GPIO输出。

## 其它需求记录

产品流程包括循迹、四角花盆、北斗经纬度、蓝牙上传、MaixCam识别、舵机插入土壤、三秒蜂鸣器报警、BH1750低照度时点亮WS2812B，当前均已接入正式业务。蓝牙使用USART1 9600 8N1，板载北斗模块实测使用USART3 9600 8N1，MaixCam使用USART2 115200 8N1。DTS波特率用于组件期望值与校验，实际外设参数仍由用户在CubeMX中设置。

## 正式四角业务

- `controlTask`和`businessTask`均以20ms周期、优先级`idle+2`运行；业务任务读取ADC38并生成轮速目标，控制任务执行左右轮速度PID。
- 上电默认停车，只通过MaixCam命令6启动；命令6仅在STOPPED或FAULT接受，成功应答后先保持停车1秒，再进入循迹。STM32在STOPPED或FAULT期间每1秒持续广播命令7；相机锁存该状态直到命令6成功，因此复位STM32后，即使相机已经进入找花盆页面，也会在右上角FPS下方恢复“启动任务”按钮。生产固件删除`stream`、`uart_cli`和各组件CLI命令，USART1改用于蓝牙。
- `encoder_register()`必须早于`control_register()`注册，使组件初始化阶段启动TIM2/TIM4 Encoder Mode。仅在CubeMX配置定时器但不注册组件，不会执行`HAL_TIM_Encoder_Start()`，表现为电机转动但里程和编码器始终为0。
- 直线基础目标为1200 rpm10。循迹位置PID初值为Kp=0.100、Ki=0、Kd=0，转向修正限制为正负300 rpm10，再叠加到左右轮速度环。
- 通道0和7是左右直角专用探头。连续3个周期确认后，以左右轮1200 rpm10同速直行1700编码器单位；补偿完成后完整停车300ms，让车身和轮速稳定，再以`+800/-800 rpm10`原地转向。停车后的编码器值才作为转弯进度起点，滑行距离不会计入转弯角度。
- 第一个转弯方向写入全局变量`g_app_course_direction`：右转为顺时针，左转为逆时针。当前默认通道0在左、通道7在右；若实车顺逆时针相反，应修正探头通道顺序，而不是修改全局语义。
- 每次转弯完成后将全局`g_app_corner_count`加一。`g_app_course_direction`只记录第一个直角的方向并在后续循环保持不变，OLED状态行显示当前直角计数`C:n/4`。
- 原来的3秒停车状态改为花盆视觉对准状态。只接受视觉启动后产生且帧龄不超过250ms的数据；连续识别3帧后才接受目标，跟踪中允许连续3帧无识别而不立即丢失。目标持续丢失后先停车300ms，再按本次搜索方向以220 rpm10原地扫描。单轮寻找最长8秒，超时后反向交替重试，最多3轮；三轮都失败才进入FAULT。首次确认花盆时记录原始中心坐标和相对目标点的X/Y误差。
- 后置摄像头目标点、死区、速度、帧确认和前后/转向/搜索极性均来自DTS`/software/flower-tracking`。当前目标为`(215,100)`，X/Y进入和保持误差范围均为正负3像素；只有连续5个新帧都位于该窗口内才完成对准。X误差生成差速转向，Y误差生成前后速度，轮速限制为700 rpm10；不增加视觉积分项。实车方向相反时修改DTS极性并重新生成编译，不在App源码增加项目宏。
- 花盆对准完成后停车并执行插土动作。舵机有效命令范围为`0..180°`，上电和复位角由`SERVO_RESET_ANGLE=0`定义；当前插土增量为65度。到位稳定300ms后保持插入2秒并读取土壤ADC，只有原始值低于动态插入阈值才算成功；成功后保持舵机位置蜂鸣报警3秒，再复位并稳定300ms。基线未就绪时拒绝启动；已启动后若300ms内没有低于阈值的数据，则不鸣叫、土壤值保持无效，安全抬起舵机并继续视觉返航。只有舵机复位失败才进入FAULT。
- 花盆对准时保存连续确认后的首次花盆中心坐标。舵机复位后重新启动视觉控制器，以该首次坐标作为目标，使后置摄像头回到进入花盆阶段时的相对位置；视觉返航最长8秒，超时进入FAULT。左右编码器去程和返程位移继续保留为诊断值，但不作为返航终止条件，因为搜索和转向可能使左右轮净位移相互抵消并导致错误的零目标。
- 视觉返航期间红外探头只采样显示，不参与电机控制。返航完成后停车，OLED在1秒内闪烁中文“完成”三次；恢复中间6路循迹时，必须等待0/7最外探头连续5个周期都释放后才重新允许直角判断，期间也不触发丢线故障。前3个直角继续下一轮，第4个直角完成后进入STOPPED。
- `servo_set_angle()`使用`int16_t`角度。实测负角度无响应，因此不再外推500us以下的脉宽；`0°=500us`，`180°=2500us`。
- 软件PWM不创建常驻任务，也不持续输出。组件记录上次命令角度，普通命令按`ceil(abs(target-last) * 200 / 45)`计算持续时间，再向上取整为完整20ms帧；当前0到65度输出15帧约300ms，`servo_reset()`固定向0度输出50帧约1秒。每帧只在500至2500us高电平脉宽期间暂停任务调度，输出低电平后立即恢复调度，并用`vTaskDelayUntil()`等待下一帧；禁止再次整段暂停300ms或1秒，否则结束时集中补算数百个FreeRTOS tick可能导致系统停滞。PA6在结束后保持低电平。
- `businessTask`执行舵机这类长操作后会把`vTaskDelayUntil()`基准重置到当前tick，不连续补跑错过的20ms周期。舵机复位后的土壤状态时间戳也在50帧实际完成后重新读取，避免使用复位前的旧tick。

## MaixCam Pro 视觉接口

花盆功能位于`camera/MaixCamPro/flower_pots`。生产MaixPy入口为`maixpy/main.py`，OpenCV对照版为`opencv/main.py`；MaixPy子目录保留其打包元数据和dist产物。MaixPy使用480x320和`find_blobs`查找浅绿色色块，屏幕侧边串口通过`maix.v1.machine.UART("/dev/ttyS0", 115200)`通信；STM32 USART2 PA2/PA3使用同波特率双向收发。

串口帧统一为`5A 5B len command payload A5`。命令1是14字节花盆目标；命令2/3采集白/黑8路ADC；命令4写内部Flash；命令5读取Flash；命令6请求启动小车业务状态机。STM32响应payload首字节为状态，后续按命令携带8路或16路`uint16_t`参数，完整布局见`protocol.md`。

命令7由STM32主动上发，表示业务处于STOPPED或FAULT且可重新启动。STM32每1秒持续广播，相机锁存该状态并在正常识别页面显示重试按钮、恢复触摸线程，直到命令6成功后才清除。

前10秒循迹校准入口只是叠加功能。稳定倒计时使用黑底黄框和大号七段数字，提高在实时画面上的可读性。10秒稳定完成后启动页提示用户按下“启动任务”，按键短暂变黄并下发命令6，随后才进入正常视觉模式；不会再自动启动。校准退出后返回启动页。原触摸取LAB阈值、白圈动画、SAVE到`/root/maixcam_threshold.json`以及保存后停止触摸线程的逻辑全部保留。

`flower_pots/opencv/main.py`目前只是旧OpenCV版本的目录迁移副本，本次不修改其协议和交互，不能代替新的MaixPy生产入口。

## OLED与蓝牙数据

OLED使用项目内18个16x16中文字模，数值使用8x16字体。页面1显示“温度、湿度、光照”，数值统一从x=48开始；页面2显示“一氧化碳、空气质量、土壤湿度”，数值统一从x=80开始。温度单位为`℃`、湿度和三个ADC传感器单位为`%`、光照单位为`lx`。MQ7、MQ135和有效土壤值按`raw/4095`显示原始满量程占比，不代表校准后的气体浓度或含水率；土壤未低于动态阈值时显示`--`。第4行只在视觉启用时显示相机X/Y，非视觉阶段保持空白，不再显示红外循迹偏移或直角计数。

蓝牙协议与已验证`uart_lanya`包络和分组顺序一致，组件builder按`uint8 -> short(int16) -> int(int32) -> float32`输出，各组数量不在线上传输。正式遥测每秒只发送一个固定36字节帧：`A5 + 已完成直角数(uint8) + 温度/湿度/MQ7/MQ135/土壤/光照/GPS纬度/GPS经度(8个float32-le) + 累加校验 + 5A`。当前short和int组为空，不发送type、长度、相机坐标或业务状态。无效数据的float固定为`0.0f`。接收方向继续使用`A5 + data[5] + 累加校验 + 5A`固定8字节帧。组件用法见`doc/components/bluetooth_开发指南.md`，实现位于`component/bluetooth`；MaixCam 和北斗分别位于 `component/maixcam`、`component/beidou`。

OpenOCD现场确认旧现象不是CPU卡死：业务进入第一个花盆后，土壤空载基线4095、阈值3895、插入采样仍为4095，300ms超时进入FAULT；FAULT主动抬起舵机并停车。该路径现已改为无效土壤数据的可恢复降级。

移除未被消费的`common_dev`字符串设备表后，正式全量构建为`0 Error(s), 0 Warning(s)`，Flash使用54344/64512字节、剩余10168字节，SRAM使用17824/20480字节、剩余2656字节；相对前一基线回收1880字节Flash和248字节SRAM。Keil调用图最大已知栈仍为business 480/1024字节、OLED 396/640字节、sensor 304/640字节；本次没有改变任务或栈配置，也没有重新烧录测量运行时水位。业务栈额外预算从固定8192字节FreeRTOS heap运行时分配，不计入链接器ZI。
