# ARK CREW SDK 新组件开发指南

本指南给出新增组件的执行顺序。架构约束见 [组件框架规范.md](组件框架规范.md)，已有组件的具体用法见 [组件开发指南索引.md](组件开发指南索引.md)。

## 1. 定义组件身份

选择表达单一能力的小写 `snake_case` 名称。简单组件保持目录名、compatible、C/H 主文件、注册函数和指南同名；组件类子组件使用 `<class>_<backend>`，并在 catalog 通过 `directory` 归入类目录。

## 2. 创建骨架

```powershell
../ark_stdio_rust/ark-studio-cli.exe --list  # 在工具参数界面填写目标，CLI 使用对应工具 ID 与 JSON 参数
```

生成后只在 `component/example/` 保留 C/H/DTS 开发文件；说明文档位于 `doc/components/example_开发指南.md`。不要在组件目录创建 README 或 manifest。

若新增的是 motor/flash/wifi 等后端，不使用简单生成器直接创建顶层目录；在现有类目录新增 `<class>_<backend>.c/.h`，catalog 填写 `directory` 和 `requires`，并通过核心内部 backend 接口附加能力。

## 3. 设计公共 API

先写调用方真正需要的能力，再设计私有实现。必须有 `bool example_register(void)`；按实际能力增加 `is_ready/read/start/stop`。所有单位写入参数或字段名，缓冲区同时提供容量，失败路径使用 `bool` 或结果枚举。

## 4. 实现生命周期

1. `register()` 注册静态 `ark_component_t` 和静态 CLI 命令。
2. `init()` 查找 `compatible = "example"`，校验全部 DTS 属性并缓存强类型配置。
3. 通过 `ark_hal_*` 或 `ark_stream` 初始化依赖，必要时创建任务。
4. `self_test()` 在有限时间内验证设备响应和关键资源。
5. 业务 API 在未就绪、参数错误、超时或设备异常时明确失败。

## 5. 添加 DTS

在目标 App 的唯一 `.dts` 中加入节点。硬件总线设备放到对应 provider 下；GPIO/PWM/ADC/encoder 使用 phandle。先运行 `--check`，再生成 `ark_dts_generated.c/.h`，禁止直接编辑生成文件。

## 6. 编写用户指南

完成 `doc/components/example_开发指南.md` 的六个固定章节。属性表必须标明必填性、类型、单位、默认值和合法范围；API 表必须覆盖公共头文件的每个函数；注意事项必须写清硬件接线、地址/波特率、任务与 ISR、超时和资源冲突。

## 7. 增加测试并验证

至少覆盖一个配置或协议成功路径，以及 disabled、缺失属性、错误 phandle、重复资源、非法范围或缓冲区边界中的一项失败路径。运行 Python 测试、DTS 检查、工程 dry-run 和目标板构建；涉及协议时增加抓包或回环验证，涉及波形时增加逻辑分析仪/示波器验证。
