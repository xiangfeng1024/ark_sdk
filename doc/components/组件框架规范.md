# ARK CREW SDK 组件框架规范

本文定义组件的代码边界、标准接口、生命周期、DTS、文档和交付要求。源码事实优先于文档；修改组件接口或配置时，必须在同一提交更新对应用户指南。

## 1. 目录与文档边界

组件源码目录只保存可编译实现，不保存 Markdown：

```text
component/<name>/
  <name>.h
  <name>.c

component/<class>/
  <class>.h/.c
  <class>_<backend>.h/.c
  <class>_<algorithm>.h/.c
  <class>_backend.h     # 仅类内部使用

doc/components/
  <name>_开发指南.md    # 对应组件的唯一用户开发指南
```

公共基础设施位于 `component/common/`。所有组件只使用 `component/common/component_catalog.json` 这一份构建清单，禁止增加第二套 manifest。组件指南统一放在 `doc/components/`，禁止在组件目录放 `README.md` 或其它 `.md`。

组件名必须使用小写 `snake_case`，并保持以下身份完全一致：

| 项目 | 标准 |
|---|---|
| 目录 | 简单组件为 `component/<name>`；类子组件由 catalog `directory` 指向 `component/<class>` |
| DTS compatible | `<name>` |
| 公共头文件 | `<name>.h` |
| 主源文件 | `<name>.c` |
| 注册函数 | `<name>_register(void)` |
| 裁剪宏 | `ARK_DTS_HAS_<NAME>` |
| catalog name | `<name>` |
| 用户指南 | `doc/components/<name>_开发指南.md` |

组件类用于同一抽象下的可替换实现或算法，不代表所有源码必须一起启用：

```text
control -> control_pid + control_line_tracking + future obstacle strategy
motor   -> motor_tb6612 | motor_can
flash   -> flash_stm32f103 + flash_w25q16
wifi    -> wifi_esp_at
ark_net -> ark_net_protocol + wifi socket
```

核心只定义稳定接口和调度，后端只翻译硬件能力，算法只计算输入到输出，协议源码只负责标准与组包。禁止核心硬编码某个后端，也禁止 Wi-Fi 驱动持有设备业务协议。

## 2. 分层边界

```text
App
  -> 组件公共 API
  -> 组件私有 context / 协议状态机
  -> ark_hal_* 或 ark_stream
  -> CubeMX / 厂商 HAL
```

组件不得直接访问 CubeMX 句柄、寄存器、IRQ 或厂商 HAL。UART 协议组件只能使用 `ark_stream_find/read/write`；物理 UART 仅由 `stream` 组件管理。ISR 只允许有界复制、计数和任务通知，解析、日志、动态分配和阻塞操作必须放在任务上下文。

## 3. 标准公共接口

每个组件必须提供：

```c
bool <name>_register(void);
```

按能力选择下列接口，不为了形式添加空实现：

```c
bool <name>_is_ready(void);
bool <name>_read(<name>_sample_t *sample);
bool <name>_start(void);
bool <name>_stop(void);
```

接口设计规则：

- 所有公开符号使用 `<name>_` 前缀，公共头文件不暴露 HAL、FreeRTOS、锁、任务句柄、协议解析状态或私有缓存。
- 可能失败的操作返回 `bool` 或明确的 `<name>_result_t`/`ark_component_result_t`；调用方必须能区分无数据、参数错误、超时和硬件失败。
- 输出通过显式指针和容量参数返回；输入缓冲使用 `const`；无参数函数写 `(void)`。
- 单位进入名称，例如 `timeout_ms`、`pulse_us`、`temperature_deci_c`、`speed_rpm10`、`duty_permille`。
- 快照结构只包含业务数据、有效标记、序列号和时间戳，不包含实现对象。

## 4. 生命周期

```text
<name>_register()
  -> framework init level ordering
  -> <name>_init()
  -> <name>_self_test()  # 支持时
  -> business API / task
```

`register()` 只注册静态组件对象和静态 CLI 命令，不访问硬件、不阻塞、不创建任务。`init()` 负责读取 DTS、校验资源、缓存强类型配置、初始化 HAL/stream，并只在确有必要时创建长期任务。`self_test()` 必须有明确的成功、失败和超时条件；不支持自检时将回调设为 `NULL`。

私有状态采用单一 context：

```c
typedef struct {
    const ark_of_node_t *node;
    bool is_ready;
    uint32_t last_error;
    /* HAL ID, stream, lock, task and cache are private. */
} <name>_context_t;
```

初始化等级：Level 1 为时间基准、看门狗等启动基础；Level 2 为 stream、CLI、USB 等传输服务；Level 3 为设备、协议和业务组件。

## 5. DTS 规则

最小节点：

```dts
example {
    compatible = "example";
    status = "okay";
};
```

资源通过父 provider、phandle、`reg`、`gpios`、`*-gpios`、`pwms` 等标准属性获得。组件专用属性使用 `ark,<property>`，单位写入属性名。禁止新增 `gpio_id`、`uart_id`、CubeMX 句柄字符串等重复配置。

缺失必填属性、类型或范围错误、未知 compatible、错误 phandle、引用 disabled provider、资源重复和容量越界必须由生成器或 `init()` 拒绝。读取完成后缓存强类型值，实时 API 不遍历 DTS。`status = "disabled"` 的节点不得生成、注册或被启用节点引用。

## 6. 用户指南标准

每个 `doc/components/<name>_开发指南.md` 必须使用统一章节：

1. `组件定位`：用途、依赖、能力边界。
2. `DTS 配置`：可运行示例、完整属性表、父子/provider 关系和生成命令。
3. `API 参考`：公共头文件中的每个 API、参数单位、返回值和失败条件。
4. `使用流程`：从 DTS 到注册、初始化和业务调用的顺序。
5. `注意事项`：接线、地址、波特率、并发、ISR、超时、容量和资源冲突。
6. `验证`：静态检查、CLI、目标板或仪器验证方法。

指南不得写“以源码为准”来代替接口说明，也不得记录尚未实现的能力。公开 API、DTS 属性、行为或限制变化时必须同步更新指南。

## 7. Catalog 与生成

`component/common/component_catalog.json` 条目示例：

```json
{
  "name": "motor_tb6612",
  "directory": "motor",
  "sources": ["motor/motor_tb6612.c"],
  "requires": ["motor"],
  "hal": ["gpio", "pwm"]
}
```

`directory` 缺省为组件名；只有组件类子组件才显式填写。`sources` 列出全部实现 `.c`，每个非 common 源文件只能归属一个条目；`requires` 声明必须同时启用的组件；`hal` 只列该条目实际依赖。生成的 `ark_dts_generated.c/.h` 不允许手工修改。

## 8. 新增组件流程

推荐使用生成器：

```powershell
../ark_stdio_rust/ark-studio-cli.exe --list  # 在工具参数界面填写目标，CLI 使用对应工具 ID 与 JSON 参数
```

生成器会创建组件 C/H、DTS 示例、集中式用户指南和 catalog 条目。随后必须完成真实实现和指南内容，增加 App DTS 节点与边界测试。

## 9. 交付检查

```powershell
../ark_stdio_rust/ark-studio-cli.exe dts.check --input doc/examples/dts-参数.json
../ark_stdio_rust/ark-studio-cli.exe dts.generate --input doc/examples/dts-参数.json
../ark_stdio_rust/ark-studio-cli.exe --list  # 在工具参数界面填写目标，CLI 使用对应工具 ID 与 JSON 参数
cargo test --manifest-path ../ark_stdio_rust/tools/sdk/Cargo.toml
git diff --check
```

固件相关变更还需执行目标 Keil 全量重建，检查 Flash、SRAM、任务栈和 MAP。不得把编译通过描述成硬件验证通过。
