# ARK CREW Studio 视觉与交互规范

## 产品方向

Studio 是面向固件工程师的 Operate 型桌面工作台。设计优先保证任务状态可信、工程上下文不丢失、异常可恢复和高频操作高效；品牌感来自排版、对齐和交互细节，不使用营销式大标题或装饰性动效。

工程控制台由四层组成：固定导航、工程上下文、工具工作区和任务抽屉。全局 Studio 日志默认折叠到状态栏，避免与当前工具的输出争夺高度。

## 视觉系统

- 画布 `#07111D`，基础表面 `#0C1B2A`，抬升表面 `#102438`，边界 `#244158`。
- 主文字 `#F3F8FC`，正文 `#D5E2EB`，辅助文字 `#A9BED0`，弱文字 `#8298AA`。
- 主操作 `#42C7F4`，成功 `#38D39F`，警告 `#F2B84B`，错误 `#FF6B7A`。
- 正文使用 Segoe UI、Microsoft YaHei UI 和 Noto Sans SC 回退链；日志和测量值使用 Cascadia Mono。
- Windows 使用 PassThrough DPI 策略、完整字体 hinting 和抗锯齿。任何长期显示的文字都不得置于图形效果中。
- 页面标题 18pt，区域标题 13.5pt，工具标题 12pt，正文 10–10.5pt，辅助信息不小于 9pt。
- 间距只使用 4、8、12、16、24、32；普通圆角 6–8px，胶囊仅用于短标签和状态。

## 工程上下文

上下文栏把页面身份、当前 App、SDK 健康度和环境操作放在同一扫描路径内。SDK 健康度必须显示通过数和需处理数，例如“23/24 通过，1 项需处理”；路径与截断值必须可查看完整内容。

## 工具工作区

- 全局搜索支持名称、说明、类别和工具 ID。
- 类型、可执行状态和排序筛选固定在工具区顶部。
- 卡片视图用于发现和理解，紧凑列表用于高频操作，两者使用同一数据源和状态语义。
- 卡片说明最多两行，标题和主操作保持稳定位置；无结果时显示清除搜索或筛选的恢复提示。
- 可执行性使用“就绪/不可运行”，与任务的“成功/失败”严格区分。
- 主操作使用具体动词，如“检查 DTS”“生成 DTS”“开始编译”“开始烧录”，不把所有副作用命令统称为“执行”。
- 卡片主体只打开工具详情，主按钮才启动任务。危险操作在详情层中确认。

## 当前任务

任务抽屉可由分隔条调整高度并记住用户设置。任务启动后自动展开，完成后停止所有运行态动画。

任务头部显示状态、App、开始时间、耗时、阶段和进度，并提供与状态匹配的再次运行、停止或关闭操作。主体分为：

- 摘要：自然语言结果、错误与警告计数、下一步操作。
- 问题：从结构化日志提取错误和警告，按级别、来源和消息排列。
- 输出：原始日志，支持查找、换行、选择和复制；用户水平滚动后不得被新日志强制拉回。
- 产物：显示名称、类型和路径；没有内容时使用明确的空状态。

运行时默认显示输出，失败时默认显示问题，成功时默认显示摘要。状态变化必须同步到工具卡、任务抽屉和底部状态栏。

## Studio 日志

底部固定 32px 状态栏，显示 Brain 状态、运行队列、警告数和错误数。Studio 日志默认折叠，用户可从状态栏或视图菜单展开；应用错误出现时自动展开。

展开后的日志支持全部、信息、警告和错误过滤，并可复制诊断信息。Studio 日志只记录应用、Brain、工作区和设置运行情况，不与工具输出混用。

## 动效与无障碍

- 页面切换使用 220ms 整页交叉淡入淡出，不改变页面几何。
- 工具详情层使用 180ms 淡入和 140ms 淡出，背景快照仅在覆盖层显示期间使用。
- 焦点边界必须清晰；图标按钮必须有可访问名称和工具提示。
- `Ctrl+K` 聚焦工具搜索，`Ctrl+J` 展开任务抽屉，`Ctrl+L` 聚焦任务输出查找，`Ctrl+R` 再次运行当前任务，`Esc` 关闭覆盖层。
- 动效只表达页面、任务和覆盖层状态；任务进入终态后停止计时器和旋转效果。

## 自适应与验收

- 默认窗口 1440×900，最小窗口 1080×680。
- 大于 1180px 使用三列工具卡，760–1180px 使用两列，更窄时使用单列。
- 1366×768 下必须同时看到工程上下文、筛选栏、至少三至四个工具入口和任务摘要。
- 1440×900、1080×680 以及 Windows 100%、125%、150% DPI 下不得出现文字重叠、裁切、状态矛盾或空白结果面板。
- 键盘导航、文本选择、日志过滤、筛选、卡片/列表切换和任务终态都必须有自动化覆盖。
